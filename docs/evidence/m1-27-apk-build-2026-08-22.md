## Toolchain / blocker disposition

The previously recorded blocker ("x86-64 aapt2 cannot start:
`/lib64/ld-linux-x86-64.so.2` missing on aarch64") is no longer present. The
execution path is **qemu-user binfmt** — the x86-64 `aapt2` runs under
user-mode emulation, NOT natively:

```text
uname -m                              -> aarch64
/proc/sys/fs/binfmt_misc/qemu-x86_64
  enabled; interpreter /usr/bin/qemu-x86_64; flags POCF
/usr/bin/qemu-x86_64                                (present)
/lib64/ld-linux-x86-64.so.2
  -> /usr/lib/x86_64-linux-gnu/ld-linux-x86-64.so.2  (x86-64 userspace loader present)
$HOME/Android/Sdk/build-tools/34.0.0/aapt2
  ELF 64-bit LSB pie executable, x86-64, dynamically linked,
  interpreter /lib64/ld-linux-x86-64.so.2
```

The former blocker is resolved because the host has a working `qemu-x86_64`
binfmt handler plus the required x86-64 userspace loader: the x86-64 Android
SDK `aapt2` therefore executes transparently under user-mode emulation on the
aarch64 host, and the AGP pipeline completes (`aapt2 version` and the full
resource-link step run under emulation). `compileSdk=34` → build-tools 34.0.0;
AGP 8.5.2 + Kotlin 1.9.24 (module pinned). The `app-debug.apk` is signed with
the default debug keystore (APK Signing Block present; `file` reports an
Android package; `apksigner` v2 verifies, 1 signer).
